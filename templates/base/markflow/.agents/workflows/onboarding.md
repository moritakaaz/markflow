# Onboarding

Purpose. This file is the SOP to interview a new user and fill the first docs.
Read when. A project just got Markflow and the PRD is still the template.
Do not read when. The PRD is already filled. Use the other workflows instead.

## Steps

1. Ask one question at a time. Wait for the answer before you ask the next one.
2. Start with the problem. What hurts today, and for whom.
3. Ask who uses the product. Ask what each user must be able to do.
4. Ask what the product must not do.
5. Read the code to learn the stack and the layout. Use only what the code shows.
6. Write PRD.md from the answers. Write ARCHITECTURE.md from the answers and from the code.
7. Mark anything you do not know as TBD. Never invent a decision or an architecture detail.
8. End with a list of open questions. The user answers them to clear the TBD marks.

## Rules

- One question per message. No lists of questions.
- Every claim in PRD.md and ARCHITECTURE.md comes from the user, from the code, or is TBD.
- Do not write code in this workflow. Docs first. Code starts after the first spec is approved.
