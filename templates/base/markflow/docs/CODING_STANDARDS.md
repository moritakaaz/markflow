## 1. Language

Code, variable names, function names, class names, file names, and folder names use English.
Docs use English for this template. Change the doc language in PRD when the project needs another language.

## 3. Function format

Write your function format here. Decide how long a function can be and how many tasks it should do. One function should do one task.

## 4. Comments

Write a comment only when logic is hard to follow without it. Use simple comments. For one line use two slashes. For many lines use slash star and star slash. Do not use decorative comment lines.

## 5. File structure

Write the order of parts in a file here. Decide what comes first, imports or constants or the main function. Then follow it.

## 6. What to avoid

Avoid em dashes. Avoid colons in prose. Avoid formal and cliché words. Avoid words like delve, leverage, seamless, robust, and cutting edge. If a sentence sounds like a sales page, rewrite it.

## 7. Enforcement

This file states intent. Config files enforce it. Examples are editor config, lint config, and format config. Keep both in sync. When a rule here changes, update the config too.
