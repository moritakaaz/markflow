## Terms

<!-- Add one entry per term. Keep each definition to one or two sentences. -->

- PRD. A product requirements document. It says what the product is for, who uses it, and what it must do. It does not say how to build it.
- Spec. A specification for one piece of work. It lists the goal, the scope, the steps, and the acceptance cases that prove the work is done. Code starts only after a spec is approved.
- Task. One small unit of work from TASKS.md. A task belongs to a spec or to a fix that is too small for a spec.
- Architecture. The layout of the system. It names the stack, the main parts, and how they connect. It also records the evidence for each choice.
- TBD. To be decided. A mark for something unknown. Never guess a TBD. Ask a human or check the code, then replace the mark with the answer.
- Evidence. Proof from the repo. A file, a test result, or a line of code that shows a claim is true. A claim without evidence is a guess.
